# ADR-0007: Single shared rules module for client and server

- **Status:** **Accepted** (2026-11-04, product owner: "accept defaults"; see OPEN_QUESTIONS §9)
- **Date:** 2026-11-03 (proposed)
- **Decided by:** needs approval ([D-9, decided])
- **Related:** D-9 · ESC-01..05, POL-02, WF-10, C-2, NFR Maintainability

## Context
- The client ladder is a port of the server's: `client/src/services/engine/escalation.ts:1` says "Ported from server/src/engine/levels.ts". The two have already drifted: the server uses `Date` and luxon [V-S `server/src/engine/levels.ts:1-40`], the client uses epoch numbers, `Intl` and adds `reachedAt` [V-C `client/src/services/engine/escalation.ts:5-30, 83`].
- The state machine and permission predicates exist only in the client [V-C `client/src/services/engine/workflow.ts`, `services/authz/permissions.ts`] and must also run on the server (C-2). Writing them twice repeats code and invites drift.
- Build facts:
  - root `package.json` already declares npm workspaces `server`, `client` [V-S `package.json`];
  - server runs TypeScript with `tsx`, `module`/`moduleResolution: nodenext`, relative imports end in `.js` [V-S `server/tsconfig.json`, `server/package.json`];
  - client uses Vite 8, `moduleResolution: bundler`, `types: ["vite/client"]` only [V-C `client/tsconfig.json`, `client/vite.config.ts`];
  - luxon is a server dependency only [V-S `server/package.json`; V-C `client/package.json`].

## Proposed decision
Create a third workspace **`shared/`** (package `@taskwatch/shared`, private, no build step) holding pure TypeScript only:
- `levels.ts` — `silenceThresholds`, `computeLevel`, `levelApplies`, `isQuietTime`, `quietEndsAt` (epoch-ms numbers, `Intl` for time zones — the client version's approach, so no luxon in the client);
- `workflow.ts` — `TRANSITIONS` (with `blocked`, ADR-0003), `canTransition`, `allowedActions`;
- `permissions.ts` — the predicates (`hasPerm` over `roles[]`, `reportsOf`, `ancestorsOf`, `isOverseer`, `canViewTask`, `assignableUsers`, `canViewUser`, `wouldCreateLoop`) written against a small data interface, not the mock `Db`;
- `types.ts` — the domain types now in `client/src/types/index.ts`.

Rules for the module: no Node or DOM APIs, no dependencies, relative imports written with `.js` extensions (valid for `nodenext`, and Vite resolves `.js` to `.ts`).

Wiring: add `"shared"` to the root `workspaces`; `shared/package.json` `exports` points at the `.ts` sources; server and client add `"@taskwatch/shared": "*"`.

## Alternatives considered
| Option | Build implications | Verdict |
|---|---|---|
| **A. npm workspace package `shared/`** (proposed) | Uses the workspace mechanism already in the repo. tsx transpiles the linked `.ts` files at run time; Vite treats a linked workspace package as source, not a pre-bundled dependency [A — both to be verified with `npm run typecheck`, `npm run dev`, `npm run dev:server` when implemented]. `tsc --noEmit` in each workspace type-checks the shared files through the import. | Recommended: no new tool, one import path. |
| B. tsconfig `paths` alias (`@shared/*`) | Needs `paths` in both tsconfigs **and** `resolve.alias` in `vite.config.ts`; tsx honours tsconfig `paths` [A]; under `nodenext`, `paths` does not apply to bare imports at run time without the loader, so it couples correctness to tsx. | Works, but three configs must stay in sync. |
| C. Relative imports (`../../shared/...`) | No config, but crosses workspace roots; server `tsconfig.include` must add the folder; brittle paths. | Not recommended. |
| D. Keep two copies | Zero build work; violates "never repeat code" and drift already exists. | Rejected by D-9's premise. |

## Consequences
- The server's tested ladder (`server/test/rules.test.ts`) must be pointed at the shared module and re-run; it now passes (21/21, `npm test` 2026-11-04) and is the regression guard for the move. Replacing luxon with `Intl` in quiet-hour math changes tested code, so the IST/PT and quiet-hour tests are the gate [A].
- The client self-check (`client/src/selfcheck.ts`) imports the shared module instead of local copies.
- Production: the server still runs through `tsx` (`server/package.json` `start`), so no separate compile step is added for `shared/`.
- If not approved, the server must re-implement `workflow.ts` and `permissions.ts`, and both ladders must be kept in sync by hand.

## Implementation note (2026-11-04, T-1.2)
- **Resolution verified.** `@taskwatch/shared` is an npm workspace, with `exports` pointing at the `.ts` sources. It resolves under the server's `nodenext` and the client's `bundler` (`npm run typecheck` exit 0), under `tsx` at run time (tests and a live server start), and in the Vite build. No `paths` aliases are needed.
- **Server.** `server/src/engine/levels.ts` is a thin `Date` ↔ epoch-ms adapter, so its callers and `rules.test.ts` are unchanged.
- **Client.** `client/src/services/engine/escalation.ts` re-exports the shared functions. `channels.ts` releases held messages at exactly the end time; it previously stepped in 15-minute increments.
- **Time zones.** The shared module uses `Intl`, not luxon. `server/test/levels-dst.test.ts` compares it with luxon every 15 minutes across the 2026 DST changes in Los Angeles, New York and India. At spring-forward, an end time inside the skipped hour now resolves to the next real occurrence; the old luxon `set().plus()` code skipped a day.
