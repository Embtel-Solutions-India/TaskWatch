# ADR-0012: Browser (Web Push) notifications

- **Status:** Accepted
- **Date:** 2026-11-11
- **Decided by:** Product owner (D-134, answered in session 2026-11-11)
- **Related:** NOTIFICATIONS-FRD (NTF-01, NTF-04, NTF-09), D-106 (WhatsApp off), ADR-0001

## Context
The owner wants TaskWatch alerts to reach people as browser notifications, including when the app is closed and on phones. In-app (the bell) only shows while a tab is open; email is slow to be noticed.

## Decision
1. **True Web Push** (W3C Push API + VAPID), not tab-only `Notification`s. The server sends with the `web-push` library; a service worker (`client/public/sw.js`) shows the notification and opens the linked page on click (same-origin URLs only).
2. **Scope: everything that reaches the bell.** `notify()` queues a `push` row next to the in-app row for every person with at least one active browser, filtered by a new per-type preference channel `push` (all types on by default; mandatory types forced on, like the other channels). Account emails and digests (HTML) never go to push.
3. **Delivery** is a fourth channel in `notifications` (`channel = 'push'`, migration 017), handled by the existing dispatcher: same lease, retries and quiet hours as email. One row sends to all of the person's browsers.
4. **Subscriptions** live in `push_subscriptions` (one row per browser endpoint, never deleted: revoked). A person manages only their own browsers (`/api/push/subscribe`, `/unsubscribe`, `/test`). A browser that signs in as someone else moves to that person. Signing out from the menu revokes the browser. A push service answering 404/410 revokes the browser.
5. **Keys** come from env only: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, optional `VAPID_SUBJECT`. Without keys the channel is simulated, like email without SMTP.
6. **Installable app:** a web-app manifest and icons, so phones can add TaskWatch to the Home Screen. iPhone/iPad support Web Push only from a Home Screen app (iOS 16.4+); Account settings explains this when needed.
7. Push rows are **not** shown in the email delivery log or the bell's delivery chips (like in-app rows).

## Consequences
- Production needs HTTPS (already required) and one VAPID key pair that never changes: a new pair silently stops every existing browser.
- Delivery depends on the browser vendor's push service; a device that is off receives the alert later (TTL 24 h).
- No new permission keys. No change to escalation rules.
