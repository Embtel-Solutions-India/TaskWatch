# ADR-0006: Keep per-entity SLA overrides

- **Status:** Accepted
- **Date:** 2026-11-03
- **Decided by:** Resolved by the work order (D-7, [OPEN_QUESTIONS.md §7.1](../../01-discovery/OPEN_QUESTIONS.md))
- **Related:** D-7, D-4 · POL-01, POL-02, ESC-01/02

## Context
- WO: "The Chief of Staff can change windows and multiples per entity without code changes; every change is logged." [WO p.3]
- Server: `sla_rules(scope text primary key, config jsonb)` with scope `'default'` or an entity id [V-S `server/src/db/migrations/001_init.sql:177-182`]; `GET /rules`, `PUT /rules/:scope`, `DELETE /rules/:scope` [V-S `server/src/routes/rules.ts:13-46`]; the engine resolves rules per task entity with `rules.for(t.entity_id)` [V-S `server/src/engine/engine.ts:51`].
- Client: one global `RulesConfig` [V-C `client/src/types/index.ts:320-329`, `api/admin.ts:222-248`].

## Decision
Keep the server's default + per-entity override model. Overrides attach to entities (= the relabelled departments, ADR-0004). The `RulesConfig` shape becomes the union of both sides: server fields `repeatAfterWindows`, `blockedAlertsLead` [V-S `server/src/domain.ts:27-44`] plus client `dueSoonHours` [V-C `types/index.ts:325`]. The Policies page gets an entity selector (UI addition, per D-7).

## Alternatives considered
| Option | Why not chosen |
|---|---|
| Single global policy (prototype) | Contradicts the WO; WO wins. |

## Consequences
- `sla_rules` stays; its JSON gains `dueSoonHours`; existing rows get the client default merged in by migration (dev data change, D-18).
- `getRules`/`setRules` take an optional entity scope; a reset endpoint removes an override ([API_CONTRACTS.md](../API_CONTRACTS.md)).
- Quiet hours and `l3NotifyCeo` are inside `RulesConfig`, so they are per-entity too (existing behaviour). Every save writes `admin_log` with before/after (existing) and re-evaluates open tasks of that entity (C-7).
